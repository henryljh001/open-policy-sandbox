# 产品范围｜Policy Sandbox

## 1. 产品命题

政策沙盒不是替领导“算出唯一答案”，而是把政策依据、行为假设、干预方案、模拟结果和不确定性放到同一条可审计链上，使决策者能够回答四类问题：

1. 规划或政策到底承诺了什么，依据在哪里？
2. 不同干预组合分别作用于谁、通过什么机制发生影响？
3. 在明确假设下，结果、分配效应和风险如何变化？
4. 哪些结论稳健，哪些高度依赖参数或外部条件？

## 2. 目标用户

| 用户 | 核心任务 | 默认输出 |
|---|---|---|
| 高层管理者 | 快速理解政策、比较方案、识别风险 | 一页纸摘要、分目标比较、支配关系与无权重 Pareto 候选集、关键假设、红线提示 |
| 政策分析人员 | 编制情景、校准参数、解释差异 | 情景对比、敏感性分析、审计记录 |
| 领域研究者 | 扩展行为规则与指标 | 插件接口、实验配置、复现包 |
| 维护者 | 管理版本、安全和公开贡献 | 测试、schema、变更与发布闸门 |

## 3. 首个领域：新型城镇化

首个领域插件已经确认，采用注册名 `new_urbanization`。它不是单一“城镇化率预测器”，而是围绕人口市民化、就业与产业、公共服务、住房、土地空间、财政约束、都市圈协同、城市更新与韧性形成条件情景系统。

官方政策四项行动构成一级模块：

1. 农业转移人口市民化；
2. 潜力地区城镇化水平提升；
3. 现代化都市圈培育；
4. 城市更新和安全韧性提升。

MVP 建议先连接前两项，模拟“迁移/落户意愿—就业机会—住房成本—公共服务容量—地方财政/土地约束”的反馈闭环。

## 4. MVP 范围

MVP 只做一个可闭环纵切：**规划目标可达性与干预组合比较**。

必备能力：

1. 导入一组带证据的结构化政策承诺；
2. 解释指标、对象、目标年、约束类型和证据定位；
3. 用结构化表单定义基线与多个政策情景；
4. 通过注册表选择模拟引擎、干预策略和评价指标；
5. 固定随机种子运行，输出总量、分组结果、不确定性与警告；
6. 比较情景并生成高层摘要和完整审计记录；
7. 导出机器可读 JSON 与可阅读报告。

## 5. MVP 非目标

- 不宣称模拟结果等同真实预测；
- 不自动选择或批准政策；
- 不默认使用大模型驱动的自由行为智能体；
- 不在首版覆盖交通、住房、公共服务的全部机制；
- 不接入个人级敏感数据；
- 不把未经人工门确认的研究候选台账作为公开数据集；
- 不以聊天界面替代结构化情景与审计链。

## 6. 用户主流程

```mermaid

    A["选择政策与证据"] --> B["确认目标和口径"]
    B --> C["配置基线与干预情景"]
    C --> D["选择模拟引擎和参数"]
    D --> E["运行与敏感性分析"]
    E --> F["比较结果、分配效应与风险"]
    F --> G["生成决策摘要和审计包"]
```

## 7. 领域模块演进

核心框架稳定后，在新型城镇化领域内部按“数据可得性 × 机制清晰度 × 决策价值”接入：

1. **市民化与县城承载**：人口迁移、就业、住房和公共服务容量；
2. **公共服务可达性**：设施布局、服务半径、人口分组受益；
3. **都市圈通勤与协同**：出行成本、就业可达性和公共服务共享；
4. **住房与城市更新**：供给、负担、存量改造和社区服务；
5. **安全韧性**：内涝、生命线和应急设施的情景压力测试。

每个领域插件必须单独声明行为假设、校准数据、适用尺度和不可外推范围。

## 8. 成功标准

MVP 成功不以“预测准确率”单一衡量，而以以下可验证结果衡量：

- 任一结果可追溯到场景、参数、引擎版本和输入证据；
- 固定种子重复运行结果一致；
- 用户能在十分钟内完成两个情景的比较；
- 报告主动显示敏感参数、外推警告和不确定性；
- 新增一个领域引擎不修改核心编排代码；
- 公开仓库隔离扫描为 0 违规。
