# 治理与安全｜Policy Sandbox

## 1. 决策责任

政策沙盒是决策支持系统，不是行政决策主体。系统可以解释依据、展示条件结果和暴露风险，但不得自动替代合法程序、专家判断、公众参与或责任主体签署。

## 2. 输出分级

| 级别 | 含义 | 显示要求 |
|---|---|---|
| 已验证事实 | 可回指来源且通过相应数据门 | 来源、定位、核验状态 |
| 模型结果 | 在给定模型和参数下得到 | 引擎、版本、种子、区间 |
| 合理推断 | 依赖明确假设的解释 | 假设和反例条件 |
| 建议 | 综合权衡后的行动选项 | 风险、适用边界、责任人 |

界面不得用同一视觉样式混淆四类内容。

## 3. 主要风险与控制

| 风险 | 控制 |
|---|---|
| 政策数字幻觉 | 事实数字必须绑定 Evidence；LLM 不写入事实字段 |
| 模型被当作预测 | 强制“条件情景”标签，报告假设、区间和外推警告 |
| 弱势群体损失被总量掩盖 | 分组指标和最差群体结果作为默认输出 |
| 敏感数据泄露 | 本地优先、私有目录隔离、最小化采集、发布前扫描 |
| 插件供应链风险 | 明确依赖、版本锁定、隔离执行、签名/审查路线 |
| 参数操纵 | 配置版本化、变更留痕、敏感性分析 |
| LLM agent 不稳定 | 默认关闭、结构化输出、多次重复、稳定性报告 |

## 4. 数据治理

真实数据接入前必须具备：来源、合法基础/许可、用途、保留期限、访问角色、去标识方法、可公开范围和数据卡。无法回答其中任一项时，不进入正式场景。

禁止默认接入：个人身份信息、精细轨迹、未授权内部材料、未公开审稿材料和无法验证来源的数据。

## 5. 模型治理

每个模型/引擎插件附模型卡，至少包括：

- 目标与非目标；
- 行为规则与因果假设；
- 校准数据与时间范围；
- 适用地域/尺度；
- 评估与敏感性结果；
- 已知失效模式；
- 版本与负责人。

跨地域、跨层级或超出训练/校准分布时，运行结果必须自动标记外推。

## 6. 人在回路

以下动作必须由人确认：事实证据发布、参数基线冻结、重大场景对比的解释、公开报告和任何带政策建议的输出。系统应记录确认人、时间、对象版本和裁决说明，但不伪造或自动填充签署。

## 7. 安全披露与发布

首次公开前确定安全联系方式、漏洞报告流程、受支持版本和响应时限。许可证未确定前不公开仓库、不接收外部贡献。
