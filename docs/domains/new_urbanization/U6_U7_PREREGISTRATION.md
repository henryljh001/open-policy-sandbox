# U6/U7 两阶段预注册协议

本协议把“先写规则、后看结果”落实为可计算的 JSON 契约。它只冻结验证设计，不接入真实数据、不运行真实校准，也不改变当前 Demo 等级。

## 1. 两个登记时点

```text
I5b 授权数据证据完成
  → 封存 U6 校准预注册（尚未查看校准结果）
  → 执行校准并形成独立 U6 证据包
  → 封存 U7 留出预注册（已查看校准结果，尚未查看留出结果）
  → 跨阶段链校验
  → 独立验证人一次性执行留出验证
  → 分别裁定 U6 与 U7
```

U6 与 U7 不能合并封存：U7 所需的最终参数和模型摘要在 U6 前并不存在。

## 2. U6 校准预注册

模板：`U6_CALIBRATION_PREREGISTRATION_TEMPLATE.json`。

封存前必须填写：

- I5b 证据包摘要；
- 校准集、留出集、分割规则、数据授权与质量报告摘要；
- 地理层级、校准期、留出方式和准入指标；
- 仓库提交、软件/引擎版本、配置、参数边界和实现冻结摘要；
- 每个总体矩的固定结果字段、单位、绝对/相对容差；
- 参数上下界、敏感性方案、失败政策和最大校准次数。

此时 `calibration_results_viewed=false`、`holdout_results_viewed=false`，最终校准参数和最终模型摘要必须为空，U7 计划也必须为空。

## 3. U7 留出预注册

模板：`U7_HOLDOUT_PREREGISTRATION_TEMPLATE.json`。

U6 完成后、首次访问留出结果前填写：

- 与 U6 相同的 I5b 证据摘要；
- 精确的 U6 预注册摘要和独立 U6 证据摘要；
- 最终校准参数摘要和最终验证模型摘要；
- 主指标、方向、阈值和汇总层级；
- 外推边界与独立验证角色。

此时 `calibration_results_viewed=true`、`holdout_results_viewed=false`。U6 计划不得重新抄写，必须通过摘要引用原登记，避免事后改写历史。

## 4. 校验与封存顺序

单份登记按以下顺序处理：

1. 用 `validation_preregistration.schema.json` 做 JSON Schema 校验；
2. 用 `validate_validation_preregistration_semantics` 检查阶段、访问状态、指标绑定、容差、版本和能力不晋级约束；
3. 用 `seal_validation_preregistration` 计算完整内容摘要并再次执行语义校验；
4. U7 封存后，用 `validate_validation_registration_chain` 与 U6 登记比对。

链校验会拒绝：U6 摘要引用不一致、I5b 证据漂移、指标范围漂移、校准/留出分割漂移、基础实现或参数边界漂移，以及 U7 时间早于 U6。

## 5. 一次性留出

U7 封存时的留出访问槽必须保持：

```json
{
  "maximum_executions": 1,
  "consumed": false,
  "consumed_at": null,
  "attempt_id": null,
  "result_digest": null
}
```

真正执行留出验证后，不修改已封存预注册；私有 U7 证据包另行记录消费时间、尝试 ID、结果摘要、失败和外推判断。需要再次运行时，原 U7 不能继续宣称一次性验证，必须按治理程序说明失效原因并建立新证据链。

## 6. 修改与失效

登记版本使用语义版本。任何影响样本、指标、容差、参数边界、实现、主验证指标、阈值或责任边界的变化均为实质修改，必须复制为新文件、提高版本并重新计算摘要。旧版保留，不覆盖、不删除。

查看校准结果后不得回改 U6；查看留出结果后不得回改 U7。若必须修改，原结果只能作为探索性信息，不能用于新登记的确认性通过证据。

## 7. 公开与私有边界

公开仓库只保存两份 `synthetic=true` 的空白模板、Schema、校验器、测试和方法说明。真实地区标识、真实文件摘要、授权材料、质量报告、参数摘要、结果摘要、审阅人和签署记录均留在经授权的私有运行环境。模板或机器测试通过不等于 I5b、U6 或 U7 通过。
