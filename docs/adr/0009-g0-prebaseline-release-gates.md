# ADR-0009：首次 Git 基线前先闭合发布边界

- 状态：Accepted
- 日期：2026-08-20

## 背景

项目已有 `0.6.0` 合成软件纵切和文件快照，但仓库尚无首个 Git 提交。文件快照不能提供 commit/tree 级来源绑定，也不能替代发布候选清单扫描。首次安全审查同时发现：原隔离脚本未严格覆盖候选清单、比较工作量可乘法放大、管理简报未做 Markdown 上下文编码、确定性入口可接受非有限数。

## 决策

1. `docs/ROADMAP.md` 的阶段 0 保持“部分完成”，直到 G0.5—G0.7 闭合；
2. G0.3 必须分别支持候选清单和 Git index 的 staged-only 扫描，遇到私有目录、重解析点、未知二进制、凭据模式、本机路径或许可冲突时 fail closed；
3. 比较任务在执行前按“情景数 × 重复次数 × 家庭样本 × 年限”计算工作量，当前本地上限为 5000 万 household-year transitions；
4. 所有进入 Markdown 管理简报的调用方文本统一做单行规范化和上下文编码；
5. JSON 公共入口、摘要和确定性计算拒绝 NaN/Infinity；
6. 上述修复不改变 Demo、U6—U8 或人工签署状态。

## 后果

- G0.1—G0.4 可以形成可审计的预基线证据；
- G0.5 初始提交、G0.6 标签与源码绑定验证、G0.7 远端/CI 状态仍须后续单独执行；
- 未取得 Git 作者信息前不得伪造提交身份；未取得真实数据授权前不得提升现实有效性能力等级。
