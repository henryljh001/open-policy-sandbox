# ADR-0010：能力状态与证据责任分离

- 状态：Accepted
- 日期：2026-08-20

## 背景

项目已经完成合成适配和校准软件闭环，但真实数据授权、数据质量、经验校准、留出验证和人工发布分别由不同证据支持。如果把软件版本、适配成功或授权状态直接写成模型有效，容易提前提升使用等级并误导管理者。

## 决策

1. 将软件证据、授权证据、有效性证据和责任证据分为四类；
2. I5b、U6、U7 和 U8 分别设置证据包、裁定责任和禁止自动推导规则；
3. 未知、缺失或冲突状态按未通过处理，禁止静默提升；
4. U6 校准与 U7 留出验证分别裁定，模型必须在查看留出结果前冻结；
5. 预注册以时间戳和内容哈希封存，查看真实结果后修改规则会使原留出证据失效；
6. 真实数据或结果进入公开边界前必须经过独立披露审查；
7. 软件语义版本不改变能力门和使用等级，U8 只能由具名人工签署。

## 后果

项目可以继续发布契约、验证器和界面能力，而不冒充真实有效性。代价是每次能力晋级都需要独立证据包和明确责任人；真实数据适配、模型校准和对外发布不能合并成一次软件验收。

权威状态定义见 `docs/CAPABILITY_EVIDENCE_MATRIX.md`。
