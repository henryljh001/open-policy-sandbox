# Policy Sandbox v0.6.0 后续执行计划

> 计划日期：2026-08-19  
> 当前结论：仅批准推进 G0 与 P1；H1 未完成前禁止进入真实数据实现  
> 执行模式：Direct mode。仓库无远端、无 HEAD、无基线提交；建立可回滚基线前不并行修改多个代码面。

## 1. 目标与不变约束

目标是把当前“合成数据可运行的 Demo”推进为开源、可审计、可复现的新型城镇化政策沙盒。系统服务于政策解读、条件情景比较、分配效应展示和风险提示，不替代正式预测、项目审批或资源配置。

后续工作必须遵守：

1. 公开仓库、私有数据环境和研究原型物理隔离；
2. 未经逐项授权，不读取、复制或软链接真实数据及相邻项目材料；
3. 真实目标包始终留在私有环境，公开代码安装到私有环境运行；
4. U6 未通过前保持 `Demo`，U8 未签署前不得标为 `Decision-support`；
5. 聚合层与家庭分配层按能力分别裁决，聚合校准不能替家庭/群体结论背书；
6. LLM 不进入事实数字链，规划措辞和总体矩拟合不自动产生因果参数；
7. 方案比较只展示分目标结果、支配关系和无权重 Pareto 候选集，不输出隐藏综合分或唯一排序；
8. 界面只消费稳定契约，不在前端重算结果或隐藏警告。

## 2. 当前事实与证据等级

### 已验证事实

- 应用版本为 `0.6.0`，状态为 `I5A_DATA_ADAPTER_PROTOCOL_IMPLEMENTED_U6_PENDING`；
- I0—I5a 的合成软件纵切已经形成：状态与守恒、七类政策工具、五类压力、重复实验、公平比较、Pareto、决策产品、适配器协议与合成校准；
- 本轮本地复验为 87 项测试通过，隔离扫描 0 违规；
- 当前有 15 份 schema、7 个合成示例和 1 个仅接受 `synthetic=true` 的汇总适配器；
- U6、U7、U8 均未通过，现实决策支持未获授权；
- Git 当前无 HEAD、无标签、无远端，项目文件尚未形成首个跟踪基线。

### 证据限制

现有测试记录和 wheel 哈希没有绑定 commit/tree hash，属于“未绑定源码的本地验证记录”。`_versions` 文件快照提供文件级归档，但不等于 Git 历史。完成 G0 前，不能宣称现有验证可由某个提交完整重放。

## 4. 执行包

### G0｜状态纠偏与可回滚基线

**依赖**：无。  
**人工输入**：项目级 Git 作者姓名/邮箱；是否建立 GitHub 远端须另行授权。

**状态（2026-08-20）**：G0.1—G0.4 `complete`；G0.5—G0.6 等待项目级 Git 作者信息；G0.7 在无远端时保持 `not_run`。证据见 `docs/validation/G0_1_TO_G0_4_VALIDATION.json`。

**任务**：

1. 将 `docs/ROADMAP.md` 的阶段 0 改为“部分完成”，明确快照不等于 Git 基线；
2. 将 `docs/PRODUCT_SCOPE.md` 的“方案排序”改为分目标比较、支配关系和无权重 Pareto 候选集；
3. 在 staged manifest 上做密钥、真实数据、本机绝对路径、许可证和敏感文件扫描；
4. 复跑测试、隔离、JSON/schema、wheel 安装和外部工作目录检查；
5. 首次提交标记为 `initial import baseline`，不声称恢复此前开发历史；
6. 创建 `v0.6.0` 标签，并生成包含 commit SHA、tree hash、命令、环境/依赖版本、日志哈希和制品哈希的新验证记录；
7. 远端未建立时 CI 明确记为 `not_run`；建立远端后再增加只使用公开依赖的基础 CI。

**交付物**：基线提交、标签、修订状态文档、源码绑定验证记录、可选 CI。  
**验证**：工作树干净；公开仓库扫描 0 违规；全套本地门通过；从标签可在干净环境构建和安装。  
**退出标准**：存在可引用的 commit/tree hash，验证记录与该提交一一对应。  
**回滚**：不以删除远端作为回滚。若发生泄露，按事件响应、凭据撤销、历史清理和重新发行处理；不使用破坏性 Git 命令。

### P1｜真实数据契约、因果声明门与能力门

**依赖**：G0。  
**目的**：在接触真实数据前冻结“允许接什么、如何拒绝、什么能力可被授权”。

**任务**：

1. 保留现有 synthetic v1 schema 和八指标合成 profile，不原地改写；
2. 新建经验 profile，逐项冻结定义、物理单位、方向、年份语义、空间层级、转换与拒绝条件，消除 `synthetic_area_unit`；
3. 新建真实目标清单、数据授权清单、来源与转换谱系、经验校准证据和 `GateRecord` 契约；授权 schema 必填合法基础、数据责任主体、访问角色、去标识方法、用途、保留期、到期/撤销、派生产物、再分发权和公开边界，并区分私有完整记录与公开脱敏摘要；
4. `GateRecord` 由独立裁决引用证据哈希，运行程序不得自行把 U6/U7/U8 写为通过；
5. 为每个“政策工具→结果”参数增加 `claim_type=assumption|literature|association|causal_estimate`、估计对象、识别设计、时间与空间尺度；
6. 除可审查的 `causal_estimate` 外，界面和报告统一使用“给定假设下的条件情景”，禁止“政策导致、政策效果、将提高”等因果措辞；U8 也不得覆盖此限制；
7. 建立能力级状态：至少区分 `aggregate_empirical`、`group_distribution_synthetic_only`、`decision_support`；
8. 增加适配器兼容性测试，覆盖未知字段、单位/年份冲突、重复记录、区划变更、缺失、授权越界和能力越权。

**预计工作量**：10—16 小时。  
**验证**：现有测试不回归；新增正反路径全通过；合成示例仍全部 `synthetic=true`；真实 schema 不允许伪装为 synthetic v1。  
**退出标准**：任何真实适配器都必须通过授权、来源、口径、因果声明和能力级门禁才能注册。  
**回滚**：新 schema 以独立版本并存，不覆写已发布契约。

### H1｜首个试点与数据授权

**依赖**：P1。  
**目的**：选择一个可闭环、可回溯、可合法使用的单一试点。

**任务**：

1. 以指标覆盖、跨期可比、官方可追溯、许可、区划稳定和决策相关性形成候选矩阵；
2. 候选阶段只审查元数据，不导入数值；
3. 由用户逐项批准来源、字段、用途、保留期、派生产物和公开边界；
4. 在看见校准结果前冻结经验 profile、空间尺度、校准集、调参规则和密封留出集；
5. 若需要数据驱动调参，至少准备独立校准/调参与留出分区，或采用预注册的嵌套/跨地区留出设计；两个时点不得同时承担调参与独立留出；
6. 单试点结论默认禁止跨地区、跨层级和跨时期外推。

**预计工作量**：4—8 小时，不含授权等待。  
**退出标准**：试点覆盖经验 profile 全部必填指标并具备独立留出；不足时必须先以新版本公开裁定必填/可选结构，不能静默放宽 `require_complete`。  
**回滚**：候选不满足硬门即淘汰，不降低许可、留出和可追溯标准。

### P2a｜披露、撤销和私有运行安全规则

**依赖**：H1。  
**目的**：隐私和派生产物控制先于真实读取器。

**任务**：

1. 定义最小单元、稀疏组合、差分查询、属性推断、模型反演、日志泄露和缓存泄露检查；
2. 建立输出白名单、抑制规则、访问日志、保留期和删除流程；
3. 真实目标包只在私有环境保存，公开仓库不接收真实数据上传；
4. 撤销谱系覆盖目标包、参数、缓存、报告和备份；不得承诺已分发副本可以召回；
5. 禁止使用“不可逆”；统一表述为“经披露风险评估、在声明攻击模型与适用条件下风险可接受”。

**预计工作量**：6—10 小时。  
**退出标准**：威胁模型与披露规则获得数据责任人批准，且能阻断一组预设攻击测试。  
**回滚**：审查失败即禁止 P2b 处理真实数值。

### P2b｜私有候选读取器与质量报告

**依赖**：P2a。  
**目的**：在独立私有环境实现一个来源读取器；公开代码安装到私有环境执行。

**任务**：

1. 私有读取器与凭据不进入公开仓库，也不与公开仓库建立软链接；
2. 输出标准记录、数据卡、来源清单、转换谱系和质量报告；
3. 单位换算、行政区划、跨期修订和缺失采用显式规则，冲突硬失败；
4. 生成最小化、经授权的私有校准目标包；
5. 候选读取器只在隔离测试注册表运行，P4 前不得公开注册。

**预计工作量**：12—20 小时。  
**验证**：记录级来源回指 100%；冻结输入重复生成相同目标包哈希；公开仓库隔离扫描 0 违规。  
**退出标准**：数据质量报告无未裁决的阻断项，授权范围覆盖所有派生输出。  
**回滚**：撤销时按 P2a 谱系处理私有目标、参数、缓存、报告与备份。

### P3｜聚合层 U6 校准候选

**依赖**：P2b。  
**目的**：检验聚合模型能否在预先冻结的指标和容差下复现总体矩，不把拟合称为因果识别或现实预测。

**任务**：

1. 在查看结果前冻结参数允许域、目标矩、损失函数、容差、停止规则和例外审批人；
2. 将参数搜索/估计器与现有目标矩评估器分开实现并分别测试；
3. 预注册量化验收表：指标、阈值、分母、区间、基准模型、参数识别标准和允许失败率；
4. 运行多随机种子、多初值校准，报告全部运行、失败率、参数稳定性和守恒检查；
5. 与保持不变、历史趋势和简化模型等透明基准比较；
6. 报告不可识别/弱识别参数、适用尺度、外推边界和禁用场景；
7. 只裁决 `aggregate_empirical` 能力。家庭分组与弱势群体结果继续标为 `synthetic_only/Demo`。

**预计工作量**：16—26 小时。  
**退出标准**：预注册量化标准全部满足并由独立 `GateRecord` 裁决，方可把聚合层 U6 标为通过；其他能力不连带升级。  
**回滚**：失败结果保留，不覆盖合成基线，不事后调低门槛。

### P4｜U7 密封留出回溯、稳健性与隐私复核

**依赖**：P3 冻结模型。  
**目的**：在模型冻结后检验留出表现和派生产物披露风险。

**任务**：

1. 对 H1 密封留出集运行回溯，不允许再次调参；
2. 报告指标级误差、区间覆盖、方向错误、失败率及相对透明基准的增益；
3. 运行阈值、压力、区划口径和参数扰动稳健性；
4. 按地区、时期、指标和能力范围分别裁决，不生成笼统的“U7 全局通过”；
5. 只有取得独立授权的真实分组基准，才评估群体误差；否则群体结论保持 `synthetic_only`；
6. 对目标包、参数、日志、报告和导出再次运行披露/重识别检查。

**预计工作量**：14—24 小时。  
**退出标准**：量化回溯门与隐私门均通过，并形成引用冻结模型和证据哈希的独立 `GateRecord`。  
**回滚**：任一子门失败，候选适配器不进入受控注册，使用等级保持 Demo。

### P5｜受控注册与稳定应用 API

**依赖**：P4。  
**目的**：只让通过能力门的适配器和模型进入统一运行生命周期。

**任务**：

1. 通过 ADR 冻结创建、校验、运行、取消、查询、比较和导出接口；
2. 增加幂等键、资源限额、超时、失败分类和审计日志；
3. 输出强制包含能力状态、U6—U8、claim type、外推警告、输入摘要和复现标识；
4. 当前只允许单用户、localhost、无真实数据上传；
5. 网络或多用户部署另立安全执行包，覆盖身份认证、授权、租户隔离、上传扫描、CSRF/CORS、日志脱敏和资源隔离。

**预计工作量**：12—18 小时。  
**退出标准**：消费者无需导入领域内部模块即可完成双方案分目标比较与审计导出；失败不产生半成品决策摘要。  
**回滚**：CLI 保持稳定入口；新 API 使用版本化路径。

### P6｜本地决策工作台候选

**依赖**：P5。  
**目的**：验证高层用户能否理解证据、假设、权衡与风险，不提前建设生产级网络平台。

**任务**：

1. 先做低保真流程和静态合成一页纸；异步任务系统和生产工作台延后；
2. 页面覆盖政策证据、基线口径、情景向导、分目标结果、Pareto 候选、群体能力状态、风险和审计导出；
3. `Demo`、U6/U7/U8、claim type 和外推警告固定在不可折叠区域；
4. 形成性测试预先定义用户资格、任务、成功率、耗时和问题严重度；代理评审只做预检；
5. 前端只渲染 P5 契约，不重算。

**预计工作量**：10—18 小时。  
**退出标准**：真实目标用户完成预定义任务并达到预注册的成功率/耗时门槛；重大问题定义清楚且阻断项为 0。  
**回滚**：界面失败不影响 CLI/API；静态一页纸保留为最小交付。

### H2 与 G8｜专家审阅和决策支持签署

**依赖**：P3、P4、P6。  
**状态**：当前明确延后。

1. H2 分别邀请领域、方法、数据治理和目标用户审阅，并保留未解决分歧；
2. G8 由授权签署人针对具体软件版本、数据版本、地区尺度、能力和用途作出签署或拒签；
3. H2 与 G8 是两个独立状态，专家审阅完成不自动等于签署；
4. 签署不能覆盖因果声明限制，也不能授权未验证的群体分配能力；
5. 新证据推翻条件时撤销能力授权并恢复受限状态。

**退出标准**：审阅角色与最低人数预先确定并披露利益冲突；所有阻断意见已关闭，或由具名风险责任人书面接受；签署记录包含软件/数据/地区/能力/用途范围、有效期、复审触发条件和撤销条件。

### P7｜稳定软件发布候选；开放生态延后

**依赖**：P6 及软件、安全、许可发布门；不以 G8 为软件发布必要条件。  
**目的**：发布可维护的软件，而不是借版本号暗示现实有效性。

**任务**：

1. 完成语义化版本、弃用政策、软件物料清单、签名制品和复现安装；
2. U8 未通过时明确发布为 Demo，禁止宣传为现实决策支持；
3. SDK、第三方模板和自动插件发布延后到至少两个独立适配器或插件证明契约稳定后；
4. 发布前执行许可证、依赖、密钥、绝对路径、隔离和文档一致性审计。

**退出标准**：全新环境可安装并复现合成示例；发布声明与能力级 GateRecord 一致；没有阻断性安全、许可或隐私问题。  
**回滚**：撤回有问题的制品并发布修订版，不改写既有标签。

## 6. 计划维护规则

1. 每个执行包使用 `planned|in_progress|blocked|complete`，并附证据路径；
2. U6—U8 或能力状态改变必须新增 `GateRecord`，不能只改 `CURRENT_STATE.md`；
3. schema 破坏性变更使用新主版本并提供迁移说明；
4. 失败证据、撤销记录和未解决分歧不覆写；
5. 每个执行包完成后运行单元测试、隔离扫描及 schema/示例互校，并写复盘台账；
6. 许可、留出、隐私或因果声明任一硬门失败时，可以继续改进软件，但禁止提高对应能力等级。

## 7. 阶段判断

项目已经完成结构清晰、可安装、可复现、可审计的合成纵切，但尚未形成源码绑定的 Git 基线，更没有现实有效性证据。当前最大缺口不是继续增加智能体复杂度或情景数量，而是：先纠正版本控制与权威状态，再冻结真实数据、因果声明和能力级契约。此后只用一个授权试点推进聚合层 U6 和密封留出 U7；家庭/群体分配能力继续保持合成演示，直到另有独立数据和隐私验证。
